# Пошаговая инструкция: как поднять свой прокси для Liv с нуля

Этот документ написан так, чтобы ты мог вообще ничего не знать про сервера,
IP-адреса и прочее — просто открываешь его рядом, и идёшь от шага к шагу.
В конце у тебя будет работающий прокси, через который Liv заходит к Google
Gemini API без VPN.

Итоговая схема выглядит так:

```
[твой браузер]  →  [Cloudflare Worker]  →  [Fly.io сервер в США]  →  [Google Gemini]
     (Беларусь)        (доступен без VPN)      (гарантированно в США)      (принимает только
                                                                           "западные" страны)
```

Нам нужны **две** части, потому что одна не справляется:

- Интернет-провайдер в РБ пропускает домен `*.workers.dev` (это Cloudflare),
  но режет домен `*.fly.dev` (это Fly.io). Поэтому браузер стучится
  **сначала** в Cloudflare.
- Cloudflare-сервер не всегда ходит к Google из разрешённой страны
  (иногда он сидит в Польше, и Google его блокирует). Поэтому из Cloudflare
  мы перенаправляем трафик в Fly.io, который **гарантированно** живёт в
  Сан-Хосе (США).

---

## Что нам понадобится

- Компьютер (Mac, Linux или Windows).
- Интернет.
- Почта для регистраций (любая, можно ту же, что для Liv).
- Для регистрации на Fly.io нужна **банковская карта** (любая, деньги не
  спишут, если не выйдешь за бесплатный тариф; у Fly.io карта нужна
  только для верификации).
- Для регистрации на Cloudflare карта не нужна.
- ~30–40 минут свободного времени.

## ЧАСТЬ 1. Fly.io — поднимаем сервер в США

Fly.io — это сервис, который даёт бесплатную виртуалку в нужной стране.
Именно она будет ходить в Google с американского IP.

### Шаг 1.1. Регистрация на Fly.io

1. Открой https://fly.io/app/sign-up в браузере.
   - Если сайт не открывается без VPN — включи VPN на этом этапе
     (только для регистрации; потом VPN можно выключить).
2. Зарегистрируйся через Google, GitHub или почту.
3. Подтверди почту (Fly.io пришлёт письмо со ссылкой).
4. После захода в дашборд тебя попросят **ввести карту** для верификации.
   Это нужно, чтобы Fly.io убедился, что ты живой человек, а не бот.
   Деньги списывать не будут, если ты не выйдешь за бесплатный тариф
   (а ты не выйдешь, если не будешь делать 1000 подключений в день).
5. После добавления карты аккаунт активен. VPN можно выключить.

### Шаг 1.2. Установка `flyctl` — утилиты командной строки

`flyctl` — это программа, через которую мы будем деплоить наш сервер.
Без неё никак: дашборд Fly.io не умеет заливать код сам, он только смотрит
на уже задеплоенные приложения.

**На macOS или Linux:**

Открой Терминал и вставь одну команду:

```bash
curl -L https://fly.io/install.sh | sh
```

Скрипт скачает `flyctl`, распакует и положит в `~/.fly/bin/flyctl`. В
конце установки он напишет что-то типа:

```
flyctl was installed successfully to /Users/ты/.fly/bin/flyctl.
Run 'flyctl --help' to get started.
```

Если после этого команда `fly` не находится — добавь в `~/.zshrc` (или
`~/.bashrc`) строчку:

```bash
export PATH="$HOME/.fly/bin:$PATH"
```

И выполни `source ~/.zshrc` (или перезапусти Терминал).

**На Windows:**

Открой PowerShell (не cmd!) от имени администратора и вставь:

```powershell
iwr https://fly.io/install.ps1 -useb | iex
```

После установки перезапусти PowerShell.

**Проверка:**

В любом терминале выполни:

```bash
fly version
```

Должен показать что-то вроде `fly v0.x.xxx`.

### Шаг 1.3. Залогиниться в Fly.io из терминала

Введи:

```bash
fly auth login
```

Эта команда откроет браузер, попросит нажать «Continue» и залогинит
`flyctl` под тем аккаунтом, на который ты зарегистрировался. После этого
в терминал вернётся «successfully logged in».

### Шаг 1.4. Скачать код прокси-сервера

Нам нужно взять папку `proxy/fly-app` из репозитория Liv. Это 2 файла:
`main.py` (код сервера) и `pyproject.toml` (список зависимостей).

Открой терминал, зайди в любую удобную папку (например Documents) и
клонируй репо:

```bash
git clone https://github.com/AnataBak/livvv.git
cd livvv/proxy/fly-app
```

Если у тебя нет `git` — просто скачай ZIP-архив репо:
1. Открой https://github.com/AnataBak/livvv
2. Жми зелёную кнопку «Code» → «Download ZIP».
3. Распакуй в любую папку.
4. В терминале зайди в `папка-куда-распаковал/livvv/proxy/fly-app`
   (например `cd ~/Downloads/livvv-main/proxy/fly-app`).

### Шаг 1.5. Создать Fly.io приложение

Находясь внутри папки `proxy/fly-app`, выполни:

```bash
fly launch --no-deploy
```

`flyctl` задаст тебе несколько вопросов. Отвечай так:

| Вопрос | Что отвечать |
| --- | --- |
| `Choose an app name` (имя приложения) | Введи что-то уникальное, например `livvv-proxy-петя` или `mylivvv-proxy-2025`. Имя будет частью адреса `<имя>.fly.dev`. |
| `Choose a region` (регион) | Введи `sjc` (Сан-Хосе, Калифорния). Это гарантированно американский регион. Если `sjc` занят — `iad` (Ashburn, VA) тоже США. |
| `Would you like to set up a Postgres database?` | `N` (нет, нам не нужна база). |
| `Would you like to set up an Upstash Redis database?` | `N` (нет). |
| `Create .dockerignore from .gitignore?` | `Y` (да) или `N` — без разницы. |
| `Would you like to deploy now?` | `N` — мы сначала проверим конфиг, потом задеплоим. |

После этого `flyctl` создаст два файла: `fly.toml` и `Dockerfile`.
Это нормально, так и должно быть.

### Шаг 1.6. Задеплоить приложение

Всё ещё находясь в папке `proxy/fly-app`, выполни:

```bash
fly deploy
```

Процесс займёт 2-4 минуты: сначала соберётся Docker-образ, потом
закачается на Fly.io, потом запустится машина. В конце должно быть:

```
Visit your newly deployed app at https://<твой-имя-приложения>.fly.dev/
```

### Шаг 1.7. Проверить, что сервер работает

Открой в браузере `https://<твой-имя-приложения>.fly.dev/health`.

Если сам `fly.dev` домен у тебя в Беларуси не открывается — это
ожидаемо, просто включи VPN для проверки этого шага (только этого шага).

Должно вернуться:

```
Liv proxy is alive. Use WebSocket to /ws/...
```

Теперь открой `https://<твой-имя-приложения>.fly.dev/debug`.
Должен быть блок `== outbound (where this server calls upstream FROM) ==`,
а внутри — строчка `loc=US`. Если `loc=US` — отлично, ты в Штатах.
Если видишь `loc=` какой-то другой страны (например `CA` — Канада) —
ничего страшного, Google принимает много стран. Главное не `RU`, `BY`,
`CN`, `IR`, `CU`.

**Запиши себе адрес:** `<твой-имя-приложения>.fly.dev` — он нужен в
следующей части.

### Шаг 1.8. Проверить, что Fly.io не засыпает в первую же минуту

По умолчанию Fly.io отправляет машину «в сон» через ~3 минуты без
запросов, чтобы экономить бесплатный тариф. Это нормально — при первом
запросе она просыпается за секунду. Но иногда эта секунда неудобна, и
тогда можно выключить автосон:

Открой файл `fly.toml` (он появился в папке `proxy/fly-app` после
`fly launch`). Найди секцию `[http_service]` и внутри неё замени:

```toml
auto_stop_machines = "stop"
```

на:

```toml
auto_stop_machines = "off"
```

Сохрани и выполни `fly deploy` ещё раз. Теперь машина всегда онлайн.

Это **необязательный** шаг. Если тебе норм первая секунда задержки
после перерыва — не трогай.

**Часть 1 закончена.** У тебя есть работающий сервер в США, доступный по
адресу `<твой-имя-приложения>.fly.dev`.

## ЧАСТЬ 2. Cloudflare Worker — фронт для браузера

Теперь поднимаем публичную точку входа на домене `*.workers.dev`,
которая не блокируется белорусскими провайдерами.

### Шаг 2.1. Регистрация на Cloudflare

1. Открой https://dash.cloudflare.com/sign-up.
   - Если сайт не открывается без VPN — опять включи VPN на минуту
     для регистрации.
2. Заведи аккаунт по почте и паролю (или через Apple/Google SSO).
3. Подтверди почту. Карту **не просят**, всё бесплатно.
4. В дашборде появится стартовая страница. Игнорируй предложения про
   домены и прочее.

### Шаг 2.2. Создать Worker

1. В левом меню выбери **Workers & Pages** → нажми кнопку
   **Create application** (или **Create Worker** если сразу видишь её).
2. Нажми **Create Worker** → «Start with Hello World!» → назови воркер
   (например `livvv-proxy-петя` или `livvv-proxy-2`) → **Deploy**.
3. Cloudflare создаст воркер и покажет его URL вида
   `https://livvv-proxy-петя.<твой-subdomain>.workers.dev`. Запиши себе
   этот URL — он будет твоим финальным адресом в настройках Liv.

### Шаг 2.3. Вставить правильный код

1. На странице воркера в правом верхнем углу нажми **`</> Edit code`**.
2. Откроется онлайн-редактор с дефолтным кодом `Hello World`.
3. **Выдели весь код** (Ctrl+A на Windows/Linux, Cmd+A на Mac) и
   удали (Delete/Backspace).
4. **Скопируй полностью** код ниже и **вставь** в редактор:

```js
// Cloudflare Worker — прокси для Gemini Live API.
//
// Этот воркер живёт на домене *.workers.dev и форвардит WebSocket
// от браузера на upstream-сервер (Fly.io), который уже умеет дойти
// до Google.

// >>> ЗАМЕНИ ЭТУ СТРОЧКУ НА АДРЕС ТВОЕГО Fly.io приложения <<<
// (без https://, без слэша в конце)
const UPSTREAM_HOST = 'livvv-proxy-петя.fly.dev';

export default {
  async fetch(request) {
    const url = new URL(request.url);
    const upgradeHeader = request.headers.get('Upgrade');

    // Любой обычный HTTP-запрос — отдаём диагностические странички.
    if (upgradeHeader !== 'websocket') {
      if (url.pathname === '/debug') {
        return debug(request);
      }
      if (url.pathname === '/' || url.pathname === '/health') {
        return new Response(
          'Liv proxy is alive. Use WebSocket to /ws/...\n',
          {
            headers: {
              'Content-Type': 'text/plain; charset=utf-8',
              'Access-Control-Allow-Origin': '*',
            },
          },
        );
      }
      return new Response('Expected WebSocket upgrade', { status: 426 });
    }

    // Тонкая, но критичная деталь: в CF Workers fetch() с заголовком
    // Upgrade: websocket нужно использовать схему https://, а не wss://.
    // С wss:// Cloudflare отвечает "Fetch API cannot load: wss://...".
    const upstreamUrl = `https://${UPSTREAM_HOST}${url.pathname}${url.search}`;

    let upstream;
    try {
      const upstreamResp = await fetch(upstreamUrl, {
        headers: { Upgrade: 'websocket' },
      });
      upstream = upstreamResp.webSocket;
      if (!upstream) {
        return new Response(
          'Failed to upgrade upstream connection (status ' + upstreamResp.status + ')',
          { status: 502 },
        );
      }
    } catch (err) {
      return new Response('Upstream connect failed: ' + (err && err.message), { status: 502 });
    }
    upstream.accept();

    const [client, server] = Object.values(new WebSocketPair());
    server.accept();

    const closeBoth = (code, reason) => {
      try { server.close(code, reason); } catch (_) {}
      try { upstream.close(code, reason); } catch (_) {}
    };

    server.addEventListener('message', (event) => {
      try {
        upstream.send(event.data);
      } catch (_) {
        closeBoth(1011, 'forward to upstream failed');
      }
    });

    upstream.addEventListener('message', (event) => {
      try {
        server.send(event.data);
      } catch (_) {
        closeBoth(1011, 'forward to client failed');
      }
    });

    server.addEventListener('close', (event) => closeBoth(event.code || 1000, event.reason || ''));
    upstream.addEventListener('close', (event) => closeBoth(event.code || 1000, event.reason || ''));
    server.addEventListener('error', () => closeBoth(1011, 'client error'));
    upstream.addEventListener('error', () => closeBoth(1011, 'upstream error'));

    return new Response(null, { status: 101, webSocket: client });
  },
};

async function debug(request) {
  const cf = request.cf || {};

  let egressTrace = 'unavailable';
  try {
    const traceResp = await fetch('https://www.cloudflare.com/cdn-cgi/trace');
    egressTrace = await traceResp.text();
  } catch (err) {
    egressTrace = 'fetch failed: ' + (err && err.message);
  }

  let upstreamHealth = 'unavailable';
  try {
    const r = await fetch('https://' + UPSTREAM_HOST + '/health');
    upstreamHealth = r.status + ' ' + (await r.text()).slice(0, 200);
  } catch (err) {
    upstreamHealth = 'upstream fetch failed: ' + (err && err.message);
  }

  const body = [
    '== inbound (where YOU hit the worker) ==',
    'colo:    ' + (cf.colo || '?'),
    'country: ' + (cf.country || '?'),
    'region:  ' + (cf.region || '?'),
    '',
    '== outbound (where the worker calls upstream FROM) ==',
    egressTrace,
    '',
    '== upstream (' + UPSTREAM_HOST + ') /health ==',
    upstreamHealth,
  ].join('\n');

  return new Response(body, {
    headers: { 'Content-Type': 'text/plain; charset=utf-8' },
  });
}
```

### Шаг 2.4. Заменить UPSTREAM_HOST на свой Fly.io адрес

В скопированном коде есть строчка:

```js
const UPSTREAM_HOST = 'livvv-proxy-петя.fly.dev';
```

Замени `livvv-proxy-петя.fly.dev` на адрес **твоего** Fly.io
приложения, который ты записал в шаге 1.7.

Например, если твоё приложение называется `mylivvv-proxy-2025`, то
должно стать:

```js
const UPSTREAM_HOST = 'mylivvv-proxy-2025.fly.dev';
```

Обрати внимание:
- **Без** `https://` спереди.
- **Без** слэша `/` в конце.
- **Внутри одинарных кавычек**.
- Точка с запятой `;` в конце строки остаётся.

### Шаг 2.5. Задеплоить воркер

В правом верхнем углу редактора нажми синюю кнопку **Deploy**
(или **Save and Deploy**). Cloudflare покажет «Worker deployed
successfully».

### Шаг 2.6. Проверить, что цепочка собралась

Открой в браузере **без VPN**:

```
https://<твой-worker-name>.<твой-subdomain>.workers.dev/debug
```

Должно вернуться что-то похожее на:

```
== inbound (where YOU hit the worker) ==
colo:    WAW
country: BY
region:  Minsk City

== outbound (where the worker calls upstream FROM) ==
fl=xxxxx
h=www.cloudflare.com
...
loc=PL
...

== upstream (mylivvv-proxy-2025.fly.dev) /health ==
200 Liv proxy is alive. Use WebSocket to /ws/...
```

Ключевая строчка: `200 Liv proxy is alive...` в секции upstream.
Это значит, что воркер успешно достукался до твоего Fly.io.
Если видишь — всё работает, можешь переходить к части 3.

**Часть 2 закончена.**

## ЧАСТЬ 3. Подключить новый прокси в Liv

1. Открой Liv в браузере.
2. Нажми шестерёнку «⚙️» (настройки).
3. Вкладка «**Настройки модели**» → листай вниз до раздела
   «**Маршрут (для стран с блокировкой)**».
4. Убедись, что галочка «**Подключаться через прокси**» включена.
5. В поле «**Адрес прокси**» **замени** текущее значение на адрес
   **твоего Cloudflare Worker'а** (без `https://`):
   ```
   <твой-worker-name>.<твой-subdomain>.workers.dev
   ```
6. Закрой настройки → нажми «**Запустить сессию**».

В журнале событий справа должно появиться:

```
Соединение через прокси: <твой-worker-name>.<твой-subdomain>.workers.dev
Подключение к Gemini Live установлено.
```

Говори — Liv должен отвечать.

## Часто задаваемые вопросы и нюансы

### Вопрос 1: Что означала ошибка «JSON.parse: unexpected character at line 1 column 2»?

Это наш самый хитрый баг. Google шлёт ответы через WebSocket **бинарными
кадрами**, внутри которых лежит JSON-текст. Когда Firefox получает
бинарный кадр через наш Cloudflare→Fly.io цепочку, он иногда
«теряет» первый байт при декодировании.

**Решение уже встроено** в `proxy/fly-app/main.py`: Fly.io сам
перекодирует бинарные кадры в текстовые перед отправкой в Cloudflare.
Тебе ничего делать не нужно — просто используй `main.py` как есть из
репо. Если кто-то перепишет это место — ошибка вернётся.

### Вопрос 2: Что означала ошибка «Fetch API cannot load: wss://»?

Cloudflare Worker'ы не умеют открывать исходящий WebSocket через схему
`wss://`. Нужно использовать `https://` + заголовок `Upgrade: websocket`.

**Решение уже встроено** в `cloudflare-worker.js`: строчка
`const upstreamUrl = \`https://${UPSTREAM_HOST}...` правильная.
Не меняй `https` на `wss` вручную — сломается.

### Вопрос 3: Что означала ошибка «User location is not supported»?

Это Google увидел, что запрос к нему пришёл с IP-адреса страны, которую
он блокирует (BY, RU, IR, CN, CU).

**Решение:** Fly.io-приложение должно быть в регионе `sjc` (США).
Проверяется через `https://<твой-fly-app>.fly.dev/debug` — там должно
быть `loc=US`.

### Вопрос 4: Почему нельзя использовать один Cloudflare без Fly.io?

Cloudflare предлагает «Smart Placement» — функцию, которая автоматически
перемещает воркер ближе к Google. Мы пробовали. Результат: воркер сел в
Польше (`loc=PL`), и Google всё равно блокировал, потому что IP-сети
Cloudflare-Польша числятся у Google как «прокси» и режутся.

Fly.io даёт явный выбор региона, поэтому мы **гарантированно** в США.

### Вопрос 5: Почему нельзя использовать один Fly.io без Cloudflare?

Белорусские (и российские) провайдеры блокируют домен `*.fly.dev` на
уровне DPI-фильтра. Когда браузер пытается открыть `*.fly.dev`, провайдер
рвёт соединение ещё до установки TLS (ошибка `PR_CONNECT_RESET_ERROR`).

Cloudflare-воркер на домене `*.workers.dev` провайдеры **не блокируют**
(потому что workers.dev — это слишком важная платформа, туда завязан
огромный кусок интернета).

### Вопрос 6: Кончится ли бесплатный тариф?

- **Cloudflare Workers**: 100 000 запросов в сутки бесплатно. Одна
  WS-сессия (весь разговор с Liv) = 1 запрос. Не кончится никогда.
- **Fly.io**: 3 бесплатные машины по 256 МБ RAM. В переводе на время —
  ~160 часов/месяц суммарно. Для одного-двух пользователей хватает.
- **Google Gemini API**: самый узкий лимит. Бесплатный тариф
  `gemini-2.5-flash` = 250 запросов/сутки. Одна сессия Liv = 1 запрос,
  как у CF. Если упрёшься — перейди на платный тариф (у Google есть
  $300 стартовых кредитов, дальше копейки).

### Вопрос 7: Как проверить, что запрос правда идёт через мой новый прокси, а не через старый?

1. Открой `https://<твой-новый-worker>.workers.dev/debug`.
2. Обнови эту страницу, пока у Liv открыт сеанс через этот прокси.
3. В Cloudflare-дашборде → Workers & Pages → твой воркер → вкладка
   **Metrics** или **Analytics** должно показывать запросы в реальном
   времени.

### Вопрос 8: Как переключаться между прокси туда-сюда?

В настройках Liv → «Маршрут» → поле «Адрес прокси» просто стираешь и
вписываешь другой адрес. Галочку отключать не нужно. Перезапусти
сессию, и Liv пойдёт через новый.

### Вопрос 9: Что делать, если `fly deploy` падает?

- Убедись, что ты находишься **внутри** папки `proxy/fly-app/` — там
  лежит `fly.toml`. Если ты в корне `livvv/`, `fly deploy` ругнётся.
- Убедись, что у тебя установлен Docker (Fly.io сам сделает образ, но
  требует Docker на локальной машине) — скачать на
  https://www.docker.com/products/docker-desktop/
- Если Fly.io пишет «machines failed to start» — запусти
  `fly logs` и посмотри, что в логах. Скорее всего опечатка в
  `pyproject.toml` или `main.py`.

### Вопрос 10: Что делать, если `/debug` у Cloudflare-воркера показывает `502` или «upstream fetch failed»?

Значит Cloudflare не может достучаться до Fly.io. Проверь:
- В коде воркера UPSTREAM_HOST точно соответствует твоему Fly.io
  приложению (правильный суффикс, без опечаток).
- Fly.io приложение живо: открой `https://<имя>.fly.dev/health`
  (с VPN, если провайдер блокирует fly.dev). Должно вернуть
  «Liv proxy is alive».
- Если Fly.io спит — первый запрос может таймаутить, сделай
  обновление страницы несколько раз.

### Вопрос 11: Можно ли поделиться прокси с другом?

Да. У твоих прокси (Cloudflare + Fly.io) нет авторизации — любой, кто
знает адрес твоего воркера, может им пользоваться, если у него есть
**свой** Gemini API-ключ. Твой ключ через прокси **не передаётся** —
он только в браузере у каждого пользователя.

Если не хочешь раздавать прокси посторонним — просто не показывай
адрес. «Угадать» публичный адрес вида `livvv-proxy-XXX.workers.dev`
практически нельзя.

Если хочешь чуть больше безопасности — в коде воркера добавь в начало
`fetch()`:

```js
if (request.headers.get('X-Proxy-Token') !== 'твой-секретный-токен') {
  return new Response('Forbidden', { status: 403 });
}
```

Тогда Liv не сможет к нему ходить без токена. Но Liv на это не
рассчитан — надо будет правку в Liv, так что этот вариант — «на вырост».

## Отладка: если что-то не работает

### «Соединение через прокси: ...» появляется, но сессия обрывается сразу

1. Проверь `https://<worker>/debug` — секция «upstream» должна вернуть
   `200 Liv proxy is alive...`. Если нет — проблема в связке
   CF↔Fly.io (неверный UPSTREAM_HOST или Fly.io упал).
2. Проверь `https://<fly-app>/debug` (с VPN) — в outbound должно быть
   `loc=US` или другая разрешённая страна. Если там `loc=RU/BY/PL` —
   нужно перевыбрать регион Fly.io: `fly regions set sjc`.

### «Сессия закрыта: User location is not supported»

Google блокирует по гео. Исправляется только тем, чтобы Fly.io сидел в
США. Убедись через `/debug`, что `loc=US`.

### «JSON.parse: unexpected character»

Ты, скорее всего, случайно не скопировал полную версию `main.py`, либо
деплоил старую версию Fly.io-приложения. Убедись, что в `proxy/fly-app/main.py`
присутствует блок:

```python
try:
    as_text = msg.decode("utf-8")
except UnicodeDecodeError:
    await client_ws.send_bytes(msg)
    continue
await client_ws.send_text(as_text)
```

Если блока нет — скопируй `main.py` из репо заново и перезадеплой
(`fly deploy`).

### Браузер пишет `PR_CONNECT_RESET_ERROR` при открытии `workers.dev`

Теоретически не должно случаться — провайдеры не блокируют
`workers.dev`. Но если вдруг — перезагрузи роутер, смени DNS на
`1.1.1.1` / `8.8.8.8`, попробуй через другую сеть.

### `fly launch` просит установить Docker

Поставь Docker Desktop с https://www.docker.com/products/docker-desktop/.
После установки перезапусти терминал.
